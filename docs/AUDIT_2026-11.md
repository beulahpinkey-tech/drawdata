# DrawData audit: November 2026

**Target:** https://draw-data.com (production) · **Date:** 2026-11-17 · **Scope:** the whole public site. There are no user accounts, so there was no authenticated scope.
**Method:** Every page was fetched over HTTP. One page per route template was loaded in a real browser at three viewport sizes. User journeys were scripted in Playwright. Security checks were passive only. The CSP was tested before deploy by injecting it into production responses. Every result below was reproduced with a script. There was no load testing, no brute force, no third-party probing, and no real form submissions (the feedback form endpoint was mocked).

---

## 1. Executive summary

The site was **up, but parts of it were wrong**. All 8,854 sitemap URLs returned 200 with valid structured data. Behind that, **the browser-side analytics for every Pick 3 and Pick 4 game had been silently showing zero data** (F-01). A page could show "14,803 draws" in its header and an all-zero matrix directly underneath. Nine states that were live were reported as "coming soon" (F-02). The security headers I had previously said were deployed only reached the ~12 static pages, not the ~8,840 edge-rendered game pages (F-03). Before the fixes, the new regression suite failed **25 of 36** data and journey tests against production.

All of those issues are fixed and deployed. After deploy, **142 of 150** executed tests pass against production. The 8 failures are a single item: HSTS is turned off by a Cloudflare dashboard setting (§4, S-01). Only the owner can change that.

**Still open, by priority:** Georgia data has not updated for 59 days because the state site was redesigned (O-01). HSTS is off at Cloudflare (S-01). Layout shift is too high on /combinations, /explore and some game hubs (P-02). The Next.js advisory can't be fixed on the current Cloudflare adapter (S-02).

**Limits.** Browser-level behaviour is proven per *template*, not per URL. Each template renders the same code for every game, so a game-specific data fault in an untested game is still possible. The data-integrity tests reduce that risk by sampling one game of each shape. Performance numbers are lab measurements from one location, not field (CrUX) data.

## 3. Functional findings

| ID | Severity | Finding | Status |
|---|---|---|---|
| F-01 | **Critical** | Pick-game draw files moved to a compact `{rows}` encoding, but four client loaders still read `mod.draws`, which was now undefined. As a result, Pairs showed "showing 0 draws" and Carryover showed 0 transitions. Check and Lookup spun forever on every state except WI/PA. The Formula Lab and Combinations had no data. Every page still returned 200 and nothing threw on the server, so uptime checks could not see it. | **Fixed.** All loaders use `getDraws()`. `npm run verify` now fails if any other file imports game JSON. |
| F-02 | High | Game lists were hard-coded to the original 5 states in 7 files. The picker opened "DrawData doesn't have New York yet" for 9 live states. The homepage grid, Lab, Explore and Patterns left out NY, CA, MA, CO, MD, FL, WA, GA and MI. | **Fixed.** All lists derive from `ALL_GAMES`. `verify` checks that every available state has a route. |
| F-04 | Medium (SEO) | Nine analytic views had no metadata of their own. As a result, 233 pages declared the *hub* as their canonical, which asks Google not to index them. 262 pages shared 27 titles. Results and number pages were also missing the "— DrawData" suffix. | **Fixed.** Each page now has its own title, description and self-canonical. The `[game]` layout re-declares the title template. |
| F-05 | Medium | On phones, two elements made the page wider than the screen, so the browser zoomed the whole page out. One was the Lab game strip (1,306 px), which my F-02 fix introduced and which was caught before deploy. The other was the number-page sparkline (640 px), which was already broken in production. The old overflow check could not detect this. | **Fixed.** The Lab uses a `<select>` and the sparkline scales to its container. The smoke test now asserts that the layout viewport matches the device width. |
| F-06 | Medium | Every results-*year* page threw React hydration error #418 because a `<div>` was nested inside a `<p>`. React then threw away the server HTML and re-rendered the page in the browser. | **Fixed.** Found after the suite was made strict. |
| F-07 | Medium | Before this deploy, React errors #329, #418, #423 and #425 were thrown on 18 of 18 sampled loads of edge pages (/learn, lookup, hubs, frequency). They did not reproduce on a local production build. Ruled out: browser timezone (tested in UTC, IST and PT), Cloudflare's injected bot-detection script (stripped it with no change), visible text differences, and edge caching (`cf-cache-status: DYNAMIC`). **After deploy: 0 of 18.** | **Resolved, cause unconfirmed.** The suite no longer tolerates any page error, so a recurrence will fail it. |
| — | Pass | Feedback form validates and submits (endpoint mocked). The age gate and cookie banner persist. The mobile menu reaches every primary page. The tab bar and back/forward work. Results month navigation works. All 6 bad URLs return 404. | — |

## 4. Security findings

Passive checks only: response headers, redirect behaviour, exposed files, TLS, and CSP compatibility. Nothing was exploited.

| ID | Severity | Finding | Status / action |
|---|---|---|---|
| F-03 | **High** | CSP, X-Frame-Options, Permissions-Policy, COOP/CORP and Referrer-Policy were missing on every edge-rendered page (~8,840), which left them open to clickjacking. Cause: Cloudflare applies `public/_headers` to static assets only, never to Functions responses. | **Fixed.** `middleware.ts` sets them on every response (`lib/security-headers.ts`). The CSP was checked against 16 game templates before deploy with 0 violations. Verified live on `/wi-pick3`, `/ny-pick4/pairs` and `/powerball/number/7`. |
| S-01 | Medium | HSTS is served as `max-age=0; includeSubDomains; preload`. Cloudflare's zone HSTS setting **overrides** the site's header, and zero disables HSTS. | **Owner action:** Cloudflare → SSL/TLS → Edge Certificates → HSTS → set Max-Age to 12 months. Keep `preload` only if you intend to submit the domain to the preload list. The 8 failing suite tests turn green once this is set. |
| S-02 | Medium | `npm audit` reports 1 critical advisory in Next 14.2.35. It was assessed as not exploitable in this configuration. It can't be patched in place because `@cloudflare/next-on-pages` supports Next ≤ 15.5.2 and is deprecated. | Track. Migrate to OpenNext on Cloudflare, then upgrade Next. |
| S-03 | Low | `script-src` allows `'unsafe-inline'` because Next's inline bootstrap needs it. A nonce-based CSP would need per-request nonces. | Accept for now. Revisit with the OpenNext migration. |
| S-04 | Low | `*.pages.dev` previews can be viewed by anyone who sends the `x-drawdata-preview` header. They serve public content and carry `noindex`. | Accept. |
| S-05 | Info | Framework fingerprint headers are exposed (`x-matched-path`, `x-edge-runtime`, `x-next-cache-tags`). Static responses carry `Access-Control-Allow-Origin: *` (Pages default; public content, no credentials). | Optional cleanup. |
| S-06 | Info | `www.draw-data.com` has no DNS record, so typing www gives a DNS error. | Add a proxied `www` CNAME. Middleware already 301s it to the apex. |
| — | Pass | No open redirects (3 probes). No exposed `.env`, `.git`, `package.json`, data files, `_worker.js` or build log. No source maps. TLS 1.3. The certificate expires 2026-12-19 and is auto-renewed by Cloudflare. | — |

## 5. Network and API

- The site has no first-party API. Data ships as static JSON chunks. The only third-party endpoints are Plausible, Cloudflare Web Analytics and Web3Forms (feedback), and the CSP allows all three.
- Failed requests seen during the browser audit: Plausible and Cloudflare challenge-script requests `ERR_ABORTED` when the page navigated away mid-request (harmless). In my test environment, **Google Fonts (`fonts.gstatic.com`) connections were closed on 67 of 147 loads**. I can't confirm whether real users see this. Self-hosting the fonts with `next/font` would remove the dependency either way (see P-03).
- An HTTP 200 was not accepted as proof of correct data. The data-integrity tests compare the browser-computed draw counts with the server-rendered header for 5 games, and check that the analytics produce non-zero results.

## 6. Performance (lab measurements, production, before this deploy)

| Metric | Desktop p50 / p90 | Mobile p50 / p90 | Target |
|---|---|---|---|
| TTFB | 972 / 1,768 ms | 940 / 1,787 ms | < 800 ms |
| FCP | 2,072 / 3,688 ms | 1,916 / 3,952 ms | < 1.8 s |
| LCP | 3,192 / 4,648 ms | 3,124 / 5,472 ms | < 2.5 s |
| JS per page (p50) | 428 KB | 375 KB | n/a |

- **P-01 (Medium):** LCP is in the "needs improvement" range on most templates. The F-06 and F-07 hydration failures forced client re-renders on many pages, so re-measure before investing further.
- **P-02 (Medium, open):** CLS above 0.1 on /combinations (0.27 desktop, 0.36 tablet), /explore (0.15–0.25), /lab tablet (0.23), /ma-pick4 tablet (0.44) and /pa-pick3/pairs tablet (0.18). These are likely client-loaded panels with no reserved height.
- **P-03 (Low):** Three Google Font families load from a third party. `next/font` would self-host them with size-adjusted fallbacks, which helps LCP and CLS.
- Edge pages are `DYNAMIC` (not cached). Because the data changes only twice a day, caching rendered HTML for a few minutes would cut TTFB.

## 8. Regression suite

`tests/e2e`, Playwright 1.61.1 (pinned to match the cached Chromium build).

```bash
npm run test:e2e                                      # against production
BASE_URL=http://localhost:3000 npm run test:e2e       # against `next start`
```

- **data-integrity:** client counts match the server header, analytics produce real results, Check and Lookup finish loading. Guards F-01.
- **journeys:** picker for every available state, homepage lists, Lab backtest, Explore/Patterns, mobile menu, tab bar and history, results paging, feedback form (mocked), age gate and cookies. Guards F-02.
- **smoke-security:** 32 templates render with no page errors and no horizontal overflow or phone zoom-out; 404s; security headers on static *and* edge pages; no off-site redirects; no exposed files. Guards F-03, F-05, F-06 and F-07.

Header, redirect and exposure tests only make sense against a deployed host. Middleware skips local hosts so that `next dev` keeps working.

Results: **before the fixes**, 25 of 36 data and journey tests failed against production. **After the fixes**, 138/138 passed on a local production build, and 142/150 passed against production. The 8 failures are S-01 only. One picker test passed only on retry, after a single 90 s page-load timeout against production.

## 9. Monitoring recommendations

No monitoring was configured as part of this audit. These are recommendations.

1. **Scheduled e2e:** run `npm run test:e2e` against production daily, and after each data-refresh commit, from GitHub Actions. This is the only check that would have caught F-01.
2. **Data freshness alert:** fail the refresh workflow, or open an issue, when `meta.json` marks any game `stale`. Today GA shows as stale and the workflow is still green.
3. **Uptime and TLS:** an external check on `/` and one game page, plus a certificate-expiry alert 14 days out.
4. **Header drift:** covered by the smoke suite once it runs on a schedule.
5. **Field performance:** watch Core Web Vitals (CrUX / Search Console) for LCP and CLS after items 4 and 6.
